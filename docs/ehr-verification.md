# eICU Demo での EHR イベント系列の合成の検証（データ共有目的）

issue #10 の検証パート。調査（[survey-ehr-synthesis.md](survey-ehr-synthesis.md)）で立てた方針に沿って、誰でも入手できる
eICU Demo で 4 手法を比べた。データ共有が目的なので、忠実度・有用性に加えてプライバシを評価した。

## 要点

1. **GPT 型の自己回帰 Transformer が忠実度・有用性で群を抜く。** コード 3-gram（0.221）は実データ同士（0.234）と同水準で、イベント間隔も最も近い。合成データで学習した死亡退院予測の AUROC は 3 シード平均 0.664（0.589〜0.788）で、他の手法（約 0.5）を大きく上回る。シード 0 は 0.788 と実データ C で学習した場合（0.770）並み。調査で見た「EHR では Transformer 系が忠実度で優位」という傾向と一致する。
2. **行独立の CTGAN は、コード分布は合うが滞在単位の情報が消える。** コード分布の JSD は 0.012 と良いが、3-gram とイベント間隔はシャッフルした実データ並みに崩れ、有用性は AUROC 0.507（当て推量）。滞在単位のラベル（死亡退院）とコードの関係が切れるため。トランザクションで時間構造が壊れたのと同じ現象が、患者単位のラベルで起きた。
3. **PAR と DGAN は今回のデータ量では有用性が出ない。** どちらも AUROC は約 0.5。DGAN はコード分布から崩れ（JSD 0.224）、PAR は系列長と時間パターンがずれた。
4. **プライバシ: 距離ベースの指標では差が小さいが、学習を進めた GPT は学習データの系列をそのまま出し始める。** メンバーシップ推論の AUC はどの手法も 0.536〜0.554 で、実データ C（0.538）との差は誤差（標準誤差 約 0.02）の範囲。一方、コードの並びが学習データの滞在と完全に一致する合成系列が、GPT（40 エポック）で 3 シード合計 2 件、120 エポックで 1 シード 3 件あった。実データ C では 0 件。多くは学習データに 1 人分しかない 5〜8 件の短い系列で、特定の患者の記録を再現している。
5. **学習を進めても有用性は上がらず、プライバシだけが悪化した。** シード 0 同士で比べると、120 エポックは 40 エポックより 3-gram（0.177）と系列長は実データ A に近づいたが、有用性は 0.788 → 0.765 と上がらず、完全一致の件数（2 → 3 件）と DCR の近さ（DCRRatio 1.005 → 0.916、3 シード平均との比較）はプライバシ悪化の方向に動いた。共有前に完全一致の系列を除外する後処理と、学習の早期打ち切りや差分プライバシなどの対策の検討が要る。

## 方法

### データ

- eICU Collaborative Research Database Demo v2.0.1（PhysioNet、ODbL v1.0）。20 病院、約 2,500 ICU 滞在
- 各 ICU 滞在で、入室から 48 時間以内の診断・治療・投薬を時刻（入室からの分）順に並べた系列にした
  - 診断・治療: `diagnosisstring` / `treatmentstring` の先頭 2 階層（例: `dx:pulmonary|respiratory failure`）
  - 投薬: HICL 番号（成分の識別子）。薬剤名は 4 割が欠損で表記ゆれも大きいため使わない。中止された指示は除外
  - 頻度上位 80 コードを残し、残りは種類ごとの `other`（`rx:other` は全イベントの 24%）
  - イベント 5 件未満の滞在は除外 → 2,127 滞在、コード 83 種類
- 属性: 年齢（"> 89" は 90）、死亡退院（`hospitaldischargestatus` が Expired）
- 患者（`uniquepid`）単位で分割: A（学習, 1,072 滞在）/ B（評価・非メンバー, 510）/ C（実データの基準, 545）。死亡退院の割合は 8.7〜9.4%

### 手法

| 手法 | 設定 | 系統 |
|---|---|---|
| ctgan | SDV CTGAN、300 エポック、`log_frequency=False`。1 行 = 1 イベント。生成行を学習データの系列長分布に従って束ね、属性は束ねた先頭行に揃える | 行独立 |
| dgan | gretel 版 DoppelGANger、1000 エポック。20 件以上の滞在の先頭 20 件（固定長）。時間間隔は log1p | 系列 GAN |
| par | SDV PAR、100 エポック。年齢・死亡退院をコンテキスト | 自己回帰（RNN） |
| gpt | 本リポジトリの最小実装（`src/transyn/seqgpt.py`）。`<bos> 属性 [コード 間隔]... <eos>` をトークン化した 3 層・d_model 128 の GPT。40 エポック。120 エポック版（gpt-e120）も 1 回 | 自己回帰 Transformer（HALO 等と同系統） |

生成数は学習データと同じ 1,072 滞在。gpt-e120 以外は 3 シード（0〜2）の平均。CPU のみ。

### 評価

| 軸 | 指標 | 定義 |
|---|---|---|
| 忠実度 | Code | コード分布の JSD |
| | Code3G | 滞在内のコード 3-gram の分布の JSD |
| | CodeTime | (コード, 入室からの 6 時間帯) の同時分布の JSD |
| | Len | 滞在あたりイベント数の Wasserstein-1 距離 |
| | Gap | イベント間隔（時間）の Wasserstein-1 距離 |
| | Mortality | 死亡退院の割合の差 |
| 有用性 | TSTR_AUROC | 生成データで死亡退院予測（ロジスティック回帰、特徴量はコードの出現回数・イベント数・年齢）を学習し、実データ B で評価した AUROC |
| プライバシ | DCR / DCRRatio | 合成の各滞在から最も近い学習データの滞在までの距離の中央値。B → A の距離との比（1 を大きく下回るとコピーの疑い） |
| | MIA | 学習データ（メンバー）と B（非メンバー）を、最も近い合成の滞在までの距離で見分けたときの AUC（0.5 が理想） |
| | ExactCopy | コードの並びが学習データのいずれかの滞在と完全に一致する合成の滞在の割合 |

基準として、実データ C（未学習の実データ）、C のコードだけ・時刻だけを行間でシャッフルしたもの、学習データ A のコピー（プライバシ最悪）を並べた。

### 読み取り

- **GPT の忠実度**: Code3G は実データ同士（0.234）並み、gpt-e120 では 0.177 とそれより小さい。これは学習データ A に寄りすぎていることを示唆する（評価は A との比較なので、A を覚えるほど値が下がる）。
- **GPT の有用性**: シードごとに 0.788・0.589・0.614 と幅が大きい。gpt-e120（シード 0）は 0.765 で、同じシードの 40 エポック（0.788）より低い。
- **CTGAN**: Code3G 0.556 はコードシャッフル（0.566）、Gap 0.575 は時刻シャッフル（0.650）とほぼ同じ。行独立であることの帰結で、トランザクション（#2）と同じ。
- **PAR**: Len 9.8・CodeTime 0.120・Gap 1.54 と系列長と時間パターンがずれた。AUROC はシード 0 が 0.610、シード 1・2 は 0.44・0.43 と 0.5 を下回った。
- **DGAN**: 固定長 20 件でしか生成できないため Len が大きく外れる（実データの中央値 22 件、範囲 5〜206 件）。コード分布も崩れている。
- **完全一致のコピー**: GPT（40 エポック）はシード 0 で 2 件（7 件の系列）、gpt-e120 で 3 件（5〜8 件の系列）。コピーされた系列のうち 4 件は学習データに 1 人分しかない並びだった。学習データ内で同じ並びを持つ滞在の組は 2 組しかなく、偶然の一致とは考えにくい。

## データ共有に向けた示唆

- 忠実度・有用性を求めるなら自己回帰 Transformer（GPT 型、HALO 等）が第一候補。ただし学習を進めるほど学習データの系列の再現が増え、有用性の上積みはなかった。
- 距離ベースのメンバーシップ推論（AUC）だけでは、少数の完全コピーを検出できない。完全一致・近似一致のチェックを共有前の必須工程にすべき。
- 対策候補: 学習の早期打ち切り（検証損失）、完全一致・近似一致する系列の除外、差分プライバシ付き学習（DP-SGD）。効果は未検証。
- eICU Demo は ODbL v1.0。派生データベース（合成データを含む可能性がある）を公開する場合の share-alike と出典表示の扱いを確認する必要がある。

## 制約

- データが小さい（学習 1,072 滞在、評価 510 滞在）。本番規模（eICU / MIMIC-IV 本体）では結果が変わり得る。本体の利用には PhysioNet の資格認定が要る
- コード体系は上位 80 種類に絞っている。実際の EHR はコードが数千〜数万種類あり、ロングテールの再現が難しくなる
- 数値（検査値・バイタル）は扱っていない
- GPT は最小実装で、HALO 等の公開実装そのものではない

## 再現手順

```bash
# eICU Demo（https://physionet.org/content/eicu-crd-demo/2.0.1/）を data/eicu_demo/ に展開しておく
uv run transyn ehr-prepare
for s in 0 1 2; do
  uv run transyn --seed $s ehr-fit ctgan --epochs 300
  uv run transyn --seed $s ehr-fit dgan --epochs 1000
  uv run transyn --seed $s ehr-fit par --epochs 100
  uv run transyn --seed $s ehr-fit gpt --epochs 40
done
uv run transyn ehr-fit gpt --epochs 120 --tag=-e120
uv run transyn ehr-evaluate
```

所要時間（CPU 12 コア、並行実行あり）: CTGAN 約 10 分、DGAN 約 2 分、PAR 約 40 分、GPT 約 12〜18 分（120 エポックで 34 分）。
