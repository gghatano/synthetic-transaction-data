# eICU DemoでのEHRイベント系列の合成の検証（データ共有目的）

issue #10の検証パート。調査（[survey-ehr-synthesis.md](survey-ehr-synthesis.md)）で立てた方針に沿って、誰でも入手できる
eICU Demoで4手法を比べた。データ共有が目的なので、忠実度・有用性に加えてプライバシを評価した。

## 要点

1. **GPT型の自己回帰Transformerが忠実度・有用性で群を抜く。** コード3-gram（0.221）は実データ同士（0.234）と同水準で、イベント間隔も最も近い。合成データで学習した死亡退院予測のAUROCは3シード平均0.664（0.589〜0.788）で、他の手法（約0.5）を大きく上回る。シード0は0.788と実データCで学習した場合（0.770）並み。調査で見た「EHRではTransformer系が忠実度で優位」という傾向と一致する。
2. **行独立のCTGANは、コード分布は合うが滞在単位の情報が消える。** コード分布のJSDは0.012と良いが、3-gramとイベント間隔はシャッフルした実データ並みに崩れ、有用性はAUROC 0.507（当て推量）。滞在単位のラベル（死亡退院）とコードの関係が切れるため。トランザクションで時間構造が崩れたのと同じ現象が、患者単位のラベルで起きた。
3. **PARとDGANは今回のデータ量では有用性が出ない。** どちらもAUROCは約0.5。DGANはコード分布から崩れ（JSD 0.224）、PARは系列長と時間パターンがずれた。
4. **プライバシ: 距離ベースの指標では差が小さいが、学習を進めたGPTは学習データの系列をそのまま出し始める。** メンバーシップ推論のAUCはどの手法も0.536〜0.554で、実データC（0.538）との差は誤差（標準誤差 約0.02）の範囲。一方、コードの並びが学習データの滞在と完全に一致する合成系列が、GPT（40エポック）で3シード合計2件、120エポックで1シード3件あった。実データCでは0件。多くは学習データに1人分しかない5〜8件の短い系列で、特定の患者の記録を再現している。
5. **学習を進めても有用性は上がらず、プライバシだけが悪化した。** シード0同士で比べると、120エポックは40エポックより3-gram（0.177）と系列長は実データAに近づいたが、有用性は0.788 → 0.765と上がらず、完全一致の件数（2 → 3件）とDCRの近さ（DCRRatio 1.005 → 0.916、3シード平均との比較）はプライバシ悪化の方向に動いた。共有前に完全一致の系列を除外する後処理と、学習の早期打ち切りや差分プライバシなどの対策の検討が要る。

## 方法

### データ

- eICU Collaborative Research Database Demo v2.0.1（PhysioNet、ODbL v1.0）。20病院、約2,500 ICU滞在
- 各ICU滞在で、入室から48時間以内の診断・治療・投薬を時刻（入室からの分）順に並べた系列にした
  - 診断・治療: `diagnosisstring` / `treatmentstring`の先頭2階層（例: `dx:pulmonary|respiratory failure`）
  - 投薬: HICL番号（成分の識別子）。薬剤名は4割が欠損で表記ゆれも大きいため使わない。中止された指示は除外
  - 頻度上位80コードを残し、残りは種類ごとの`other`（`rx:other`は全イベントの24%）
  - イベント5件未満の滞在は除外 → 2,127滞在、コード83種類
- 属性: 年齢（"> 89" は90）、死亡退院（`hospitaldischargestatus`がExpired）
- 患者（`uniquepid`）単位で分割: A（学習, 1,072滞在）/ B（評価・非メンバー, 510）/ C（実データの基準, 545）。死亡退院の割合は8.7〜9.4%

### 手法

| 手法 | 設定 | 系統 |
|---|---|---|
| ctgan | SDV CTGAN、300エポック、`log_frequency=False`。1行 = 1イベント。生成行を学習データの系列長分布に従って束ね、属性は束ねた先頭行に揃える | 行独立 |
| dgan | gretel版DoppelGANger、1000エポック。20件以上の滞在の先頭20件（固定長）。時間間隔はlog1p | 系列GAN |
| par | SDV PAR、100エポック。年齢・死亡退院をコンテキスト | 自己回帰（RNN） |
| gpt | 本リポジトリの最小実装（`src/transyn/seqgpt.py`）。`<bos> 属性 [コード 間隔]... <eos>`をトークン化した3層・d_model 128のGPT。40エポック。120エポック版（gpt-e120）も1回 | 自己回帰Transformer（HALO等と同系統） |

生成数は学習データと同じ1,072滞在。gpt-e120以外は3シード（0〜2）の平均。CPUのみ。

### 評価

| 軸 | 指標 | 定義 |
|---|---|---|
| 忠実度 | Code | コード分布のJSD |
| | Code3G | 滞在内のコード3-gramの分布のJSD |
| | CodeTime | (コード, 入室からの6時間帯) の同時分布のJSD |
| | Len | 滞在あたりイベント数のWasserstein-1距離 |
| | Gap | イベント間隔（時間）のWasserstein-1距離 |
| | Mortality | 死亡退院の割合の差 |
| 有用性 | TSTR_AUROC | 生成データで死亡退院予測（ロジスティック回帰、特徴量はコードの出現回数・イベント数・年齢）を学習し、実データBで評価したAUROC |
| プライバシ | DCR / DCRRatio | 合成の各滞在から最も近い学習データの滞在までの距離の中央値。B → Aの距離との比（1を大きく下回るとコピーの疑い） |
| | MIA | 学習データ（メンバー）とB（非メンバー）を、最も近い合成の滞在までの距離で見分けたときのAUC（0.5が理想） |
| | ExactCopy | コードの並びが学習データのいずれかの滞在と完全に一致する合成の滞在の割合 |

基準として、実データC（未学習の実データ）、Cのコードだけ・時刻だけを行間でシャッフルしたもの、学習データAのコピー（プライバシ最悪）を並べた。

### 読み取り

- GPTの忠実度: Code3Gは実データ同士（0.234）並み、gpt-e120では0.177とそれより小さい。これは学習データAに寄りすぎていることを示唆する（評価はAとの比較なので、Aを覚えるほど値が下がる）。
- GPTの有用性: シードごとに0.788・0.589・0.614と幅が大きい。gpt-e120（シード0）は0.765で、同じシードの40エポック（0.788）より低い。
- CTGAN: Code3G 0.556はコードシャッフル（0.566）、Gap 0.575は時刻シャッフル（0.650）とほぼ同じ。行独立であることの帰結で、トランザクション（#2）と同じ。
- PAR: Len 9.8・CodeTime 0.120・Gap 1.54と系列長と時間パターンがずれた。AUROCはシード0が0.610、シード1・2は0.44・0.43と0.5を下回った。
- DGAN: 固定長20件でしか生成できないためLenが大きく外れる（実データの中央値22件、範囲5〜206件）。コード分布も崩れている。
- 完全一致のコピー: GPT（40エポック）はシード0で2件（7件の系列）、gpt-e120で3件（5〜8件の系列）。コピーされた系列のうち4件は学習データに1人分しかない並びだった。学習データ内で同じ並びを持つ滞在の組は2組しかなく、偶然の一致とは考えにくい。

## データ共有に向けた示唆

- 忠実度・有用性を求めるなら自己回帰Transformer（GPT型、HALO等）が第一候補。ただし学習を進めるほど学習データの系列の再現が増え、有用性の上積みはなかった。
- 距離ベースのメンバーシップ推論（AUC）だけでは、少数の完全コピーを検出できない。完全一致・近似一致のチェックを共有前の必須工程にすべき。
- 対策候補: 学習の早期打ち切り（検証損失）、完全一致・近似一致する系列の除外、差分プライバシ付き学習（DP-SGD）。効果は未検証。
- eICU DemoはODbL v1.0。派生データベース（合成データを含む可能性がある）を公開する場合のshare-alikeと出典表示の扱いを確認する必要がある。

## 制約

- データが小さい（学習1,072滞在、評価510滞在）。本番規模（eICU / MIMIC-IV本体）では結果が変わり得る。本体の利用にはPhysioNetの資格認定が要る
- コード体系は上位80種類に絞っている。実際のEHRはコードが数千〜数万種類あり、ロングテールの再現が難しくなる
- 数値（検査値・バイタル）は扱っていない
- GPTは最小実装で、HALO等の公開実装そのものではない
- DGANは学習用の602系列をバッチ602（系列数）で学習したため、1エポックあたり1回、1000エポックで1,000回しか更新していない。ICUバイタルの検証（#15）ではバッチを64に下げると時間構造の再現が大きく改善しており、ここでのDGANの結果は学習不足の可能性がある。#17でバッチ64で再実験すると、有用性はAUROC 0.650とGPT型とほぼ同等になった（[dgan-rerun.md](dgan-rerun.md)）

## 再現手順

```bash
# eICU Demo（https://physionet.org/content/eicu-crd-demo/2.0.1/）を data/eicu_demo/ に展開しておく
uv run transyn ehr-prepare
for s in 0 1 2; do
  uv run transyn --seed $s ehr-fit ctgan --epochs 300
  uv run transyn --seed $s ehr-fit dgan --epochs 1000
  uv run transyn --seed $s ehr-fit par --epochs 100
  uv run transyn --seed $s ehr-fit gpt --epochs 40
done
uv run transyn ehr-fit gpt --epochs 120 --tag=-e120
uv run transyn ehr-evaluate
```

所要時間（CPU 12コア、並行実行あり）: CTGAN約10分、DGAN約2分、PAR約40分、GPT約12〜18分（120エポックで34分）。
