# Banksformer（ECML PKDD 2022）Czech実験の追試

issue #2の成果物。調査（issue #1, [survey-gan-transaction-synthesis.md](survey-gan-transaction-synthesis.md)）を受けて、
系列手法と行独立手法の差を実データで確かめた。

## 要点

1. **論文の評価指標（Table 2）では、行独立のCTGANが系列手法と同等以上に見える。** 修正後のCTGANはTcode・CF・(Tcode, DoM) で論文のBFに近い値を出し、今回のDGAN・PARより良い。しかし取引間隔（TD）と月あたり取引件数（TxPerMonth）は、実データの日付をランダムに入れ替えたものと同程度に崩れている。Table 2の6指標だけでは、行独立であることによる破綻を検出できない。これはissue #1で引いた [S1][S2] の指摘と一致する。
2. **CF（月次キャッシュフロー）は時間構造の崩れに鈍い。** 実データの日付をシャッフルしてもCFは2,328で、論文のBF（2,738）より小さい。CFの大小を時間構造の再現度として読むのは危険。
3. **論文DGとの一致は部分的。** DoM（0.107 vs 0.090）とCFの桁（4万vs 5.8万）は論文のDGに近い。一方、Tcode 3-gramは論文のDG（0.132）が順序を学習していたのに対し、今回のDGAN（0.220）はtcodeをシャッフルした基準（0.186）より悪く、順序を学習できていない。実装・前処理の差（後述）が効いている可能性が高い。
4. **どのモデルも日付パターン（DoM）は論文のBFに遠く及ばない。** CTGAN・PAR・DGANはいずれもDoMが0.10前後で、BFの0.011と大きな差がある。BFは未実行だが、「汎用の生成モデルは月内の日付パターンを学習しにくい」という論文の主張とは整合する。
5. **ツール側の落とし穴が3つあった。** どれも結果を大きく変えるが、エラーにはならない。
   - SDVのCTGANは既定（`log_frequency=True`）のままだと、生成時のカテゴリ分布が一様分布側に平らになる（Tcode JSD 0.000 → 0.130）
   - pandas 3のdatetime（マイクロ秒単位）をSDVにそのまま渡すと、生成日付が1970年付近に化ける
   - gretel版DGANに取引間隔をそのまま渡すと、全取引が同じ日になる系列ばかりを生成した

## 追試の対象

Nickerson et al., *Banksformer: A Deep Generative Model for Synthetic Transaction Sequences*, ECML PKDD 2022の
Table 2（Czechデータ）。論文はBanksformer（BF）をDoppelGANger（DG）・TimeGAN（TG）と6つの指標で比較している。

今回は次の2点を確かめた。

1. 評価プロトコルの再現: 論文の前処理と指標を再実装し、DG相当のモデルで論文に近い傾向が出るか。
2. CTGANの素朴な適用: 論文にない行独立のCTGANを同じ指標で測り、行単位の指標と系列・日付の指標がどう分かれるか（issue #1の問い）。

Banksformer本体の再学習は行っていない（「残課題」参照）。

## 方法

### データと前処理（論文2節に準拠）

- 著者リポジトリの前処理済みCSV（Czech bank, 105.6万取引, 4,500口座）
- tcode = type × operation × k_symbol（16種類。論文と一致）
- 口座ごとに日付順に並べ、80件ずつに分割し、20件未満の系列を除外 → 14,354系列
- 口座単位で半分に分割: A（学習用, 7,259系列）とB（比較用, 7,095系列）

### 指標

| 列 | 定義 | 出典 |
|---|---|---|
| Amt | 取引金額のWasserstein-1距離 | 論文Table 2 |
| CF | 月次キャッシュフロー（系列×月ごとの入金−出金の合計）のWasserstein-1距離 | 論文Table 2 |
| Tcode | tcode分布のJSD | 論文Table 2 |
| DoM | 月内日（1〜31）の分布のJSD | 論文Table 2 |
| Tcode3G | 系列内tcode 3-gramの分布のJSD | 論文Table 2 |
| TcodeDoM | (tcode, 月内日) 同時分布のJSD | 論文Table 2 |
| TD | 系列内の取引間隔（日）のWasserstein-1距離 | 著者コードで集計されているがTable 2には未掲載 |
| TxPerMonth | 系列×月ごとの取引件数のWasserstein-1距離 | 本追試で追加 |

JSDは著者コードに合わせて自然対数（最大値ln 2 ≈ 0.693）。生成データは学習データAと比較する（論文も学習データと比較している）。

指標の目安として、実データBを使った基準を3つ併記する。

- Real-B: そのまま。同じ分布から独立に取った実データ同士の値
- tcodeシャッフル: Bのtcodeだけを全行でランダムに入れ替えたもの。周辺分布は保ち、順序と金額・日付との対応を崩す
- 日付シャッフル: Bの日付だけを全行でランダムに入れ替えたもの。系列の時間構造を崩す（行独立な生成の理想形に近い）

### 比較した手法

| 手法 | 実装 | 学習設定 | 論文との関係 |
|---|---|---|---|
| dgan | gretel-synthetics 0.22.2のDoppelGANger（PyTorch） | 400エポック。属性: 年齢・系列開始日、特徴量: tcode・log金額・log(1+取引間隔) | 論文DGの再実装版 |
| ctgan | SDV 1.38.5 / ctgan 0.12.1の`CTGANSynthesizer`、`log_frequency=False` | 50エポック。1行 = 1取引（日付・tcode・金額・年齢）。生成行を80件ずつ束ねて系列とみなす | 論文になし。issue #1の問い |
| ctgan-logfreq | 同上、SDV既定の`log_frequency=True` | 同上 | 既定設定のまま使った場合の参考 |
| par | SDVの`PARSynthesizer` | 50エポック。系列キー・日付順・年齢をコンテキスト | 論文になし。SDVの系列手法 |

いずれも生成数は論文と同じ5,000系列、乱数シード0。CPUのみ（12コア）。所要時間はDGAN 5分、CTGAN 12〜24分、PAR 63分（CTGANの一方はPARと並行実行）。

### 論文との差分

| 項目 | 論文 | 本追試 | 影響 |
|---|---|---|---|
| DGの実装 | 元のTensorFlow実装、可変長系列 | gretel-syntheticsのPyTorch実装、長さ80の系列のみで学習・生成 | 系列長の分布は再現対象外 |
| DGの時刻表現 | 開始日＋取引間隔 | 同じ。ただし取引間隔はlog1pで圧縮（付録A） | 生の取引間隔だと崩壊した |
| 生成値の範囲 | 記載なし | DGANは学習データの範囲にクリップ（SDV系は既定で同様） | 外れ値の影響を抑える |
| 比較対象の実データ | 学習に使った全データ | 学習用の半分（A） | 系列数が約半分 |
| 乱数シード | 記載なし | 1シードのみ | ばらつきは未評価 |
| BF・TG | 実行 | 実行せず | BF・TGの行は論文値を転記 |

### 読み取り

CTGANは「日付シャッフル」とほぼ同じ振る舞いをする。TD（18.3 vs 21.4）、TxPerMonth（3.4 vs 3.7）、CF（2,172 vs 2,328）、Tcode3G（0.192 vs 0.169〜0.186）のどれも、実データの日付やtcodeを行間で入れ替えた基準と同程度になった。CTGANが生成した80件の「系列」は平均1,861日（約5年）に散らばっていて、実データの1系列（平均379日）とは時間の密度がまったく違う。それでもTable 2の6指標では、CTGANはBFに近い値を出す。

系列モデルは時間間隔を学習するが、順序・日付パターンは今回の設定では学習できていない。PARとDGANはTDを2.4〜2.5まで下げ（CTGANの約1/7）、PARは月あたり件数もよく合っている（0.36）。一方Tcode3Gは0.22とtcodeシャッフルの基準（0.186）より悪く、取引コードの並び順は再現できていない。DoMとTcodeDoMもCTGANと同程度で、月末の利息計上のような日付と取引種別の結びつきは学習されていない。

論文DGとの比較。DoM（0.107 vs 0.090）とCFの大きさ（4.0万対5.8万）は論文のDGと同じ水準で、「DGは日付パターンを学習しにくく、キャッシュフローが大きく外れる」という論文の観察は再現した。一方で次の2点は論文のDGと違う。

- Tcode3G: 論文のDG（0.132）はシャッフル基準より良く、順序をある程度学習していた。今回のDGAN（0.220）は学習できていない
- TcodeDoM: 今回のDGAN（0.282）は論文のDG（0.660）よりかなり良い。論文の値はtcodeシャッフル基準（0.211）よりも悪く、生成された日付の分布自体が大きく崩れていた可能性がある

固定長への制限、取引間隔のlog変換、PyTorch実装への置き換えのどれが効いたのかは切り分けていない。

なお、今回のDGANは系列の開始日（属性）が崩壊していた。生成された5,000系列の開始日はすべて1998年5月以降で、取引日は実データの期間（1993〜1998年）を越えて2002年まで伸びている。月内日や取引間隔の指標には直接効かないが、年・季節に関わる分析には使えない。

CFは時間構造の指標として解釈しにくい。日付シャッフルのCF（2,328）は論文のBF（2,738）より小さい。また、tcodeシャッフルのCF（10,817）は日付シャッフルより大きく、CFはむしろ入出金の符号（tcode）と金額の対応に敏感な指標である。CFの小ささを「時系列パターンを捉えた証拠」とする論文6.1節の読み方には注意が要る。

## 結論

- 論文の評価プロトコルは再実装できた。DG相当のモデルで、日付パターン（DoM）とキャッシュフロー（CF）の弱さは論文と同じ傾向が出た。ただし3-gramと (Tcode, DoM) は論文値と一致しなかった。
- issue #1の問い（CTGANを素で適用すると何が崩れるか）への実データでの答え: 行単位・同時分布の指標はほぼ保たれる一方、取引間隔と取引密度が実データの日付をランダムに入れ替えた場合と同じ程度に崩れる。この崩れ方は論文Table 2の指標では見えず、TD・TxPerMonthのような時間構造の指標を直接入れないと検出できない。
- 汎用の系列モデル（PAR, DGAN）は時間間隔を改善するが、取引コードの順序と月内の日付パターンは、今回の学習量ではBFの水準に届かない。

## 残課題

- Banksformer本体の再学習 → #6で実施（[banksformer-rerun.md](banksformer-rerun.md)）
- 複数シードでのばらつき評価 → #4で実施（本レポートの追記）
- DGANの論文との差（3-gram, TcodeDoM）の切り分け → #5で実施（[dgan-ablation.md](dgan-ablation.md)）
- DGANの更新回数: バッチ1,000で学習したため、400エポックで2,400回しか更新していない。ICUバイタルの検証（#15、[icu-vitals-verification.md](icu-vitals-verification.md)）では、更新回数を増やすと時間構造の再現が大きく改善した。本レポートのDGANの値は学習不足の可能性がある。#17でバッチ64で再実験すると、3-gramは0.096と論文のDGを上回った（[dgan-rerun.md](dgan-rerun.md)）

## 追記: シード間のばらつき（#4）

dgan・ctgan・parをシード0〜2の3回ずつ学習・生成した（ctgan-logfreqはシード0のみ）。値は平均 ± 標準偏差。

| | Amt | CF | Tcode | DoM | Tcode3G | TcodeDoM | TD | TxPerMonth |
|:--|--:|--:|--:|--:|--:|--:|--:|--:|
| ctgan | 1,243 ± 1,023 | 3,087 ± 819 | 0.000 ± 0.000 | 0.104 ± 0.005 | 0.190 ± 0.001 | 0.271 ± 0.008 | 18.93 ± 0.58 | 3.54 ± 0.14 |
| par | 2,996 ± 73 | 13,728 ± 1,779 | 0.032 ± 0.014 | 0.109 ± 0.000 | 0.261 ± 0.039 | 0.302 ± 0.023 | 2.03 ± 0.44 | 0.46 ± 0.15 |
| dgan | 16,060 ± 15,241 | 47,273 ± 44,388 | 0.023 ± 0.008 | 0.110 ± 0.002 | 0.268 ± 0.092 | 0.283 ± 0.006 | 10.25 ± 11.94 | 2.38 ± 1.09 |

- 本文の結論はシードに依存しない。CTGANは3回ともTable 2の指標（Tcode・CF・TcodeDoM）が良く、取引間隔と月あたり件数が日付シャッフル並みに崩れる。標準偏差も小さく、行独立であることによる構造的な結果と言える。
- PARは安定している。取引間隔と月あたり件数は、平均でCTGANの約1/8〜1/9。ただし系列長はシードで35〜58件と変わる（PARは系列長も学習する）。
- DGANは不安定。取引間隔のW1距離はシードによって2.4〜24.0、金額の平均は実データの0.3〜6.6倍。本文のDGANの値（シード0）は3回のうち良い側だった。詳細は[dgan-ablation.md](dgan-ablation.md)（#5）。

再現手順: `uv run transyn --seed 1 fit <model> --epochs <n>`のように`--seed`を付けて実行すると、`outputs/gen_<model>_s<seed>.csv.gz`に保存され、`uv run transyn evaluate`がシード平均と標準偏差を出す。

## 付録A: DGANの設定による違い

同じ400エポック・2,000系列生成で、取引間隔の渡し方とスケーリングだけを変えた結果（クリップなし）。

| 設定 | 生成された取引間隔の平均（日） | Amt | CF | Tcode3G | TD |
|---|--:|--:|--:|--:|--:|
| 既定・取引間隔そのまま | 0.01 | 3,001 | 224,590 | 0.181 | 5.28 |
| 既定・log1p(取引間隔) | 7.64 | 51,143 | 167,198 | 0.222 | 2.45 |
| example scalingなし・そのまま | 13.82 | 56,871 | 151,250 | 0.431 | 9.94 |
| example scalingなし・log1p | 3.46 | 3,387 | 18,342 | 0.465 | 2.15 |

実データの取引間隔の平均は5.3日。既定設定のままだと取引間隔が0に潰れ、全取引が同じ日に置かれた。本編では「既定・log1p」を採用し、金額の外れ値は学習データの範囲へのクリップで抑えた。設定次第で指標が1桁変わるので、論文のDGの値との比較は幅を持って読む必要がある。

## 再現手順

```bash
uv sync
uv run transyn prepare
uv run transyn fit dgan --epochs 400
uv run transyn fit ctgan --epochs 50
uv run transyn fit ctgan-logfreq --epochs 50
uv run transyn fit par --epochs 50
uv run transyn evaluate
```
