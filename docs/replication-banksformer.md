# Banksformer（ECML PKDD 2022）Czech 実験の追試

issue #2 の成果物。調査（issue #1, [survey-gan-transaction-synthesis.md](survey-gan-transaction-synthesis.md)）を受けて、
系列手法と行独立手法の差を実データで確かめた。

## 要点

1. **論文の評価指標（Table 2）では、行独立の CTGAN が系列手法と同等以上に見える。** 修正後の CTGAN は Tcode・CF・(Tcode, DoM) で論文の BF に近い値を出し、今回の DGAN・PAR より良い。しかし取引間隔（TD）と月あたり取引件数（TxPerMonth）は、実データの日付をランダムに入れ替えたものと同程度に崩れている。Table 2 の 6 指標だけでは、行独立であることによる破綻を検出できない。これは issue #1 で引いた [S1][S2] の指摘と一致する。
2. **CF（月次キャッシュフロー）は時間構造の崩れに鈍い。** 実データの日付をシャッフルしても CF は 2,328 で、論文の BF（2,738）より小さい。CF の大小を時間構造の再現度として読むのは危険。
3. **論文 DG との一致は部分的。** DoM（0.107 vs 0.090）と CF の桁（4 万 vs 5.8 万）は論文の DG に近い。一方、Tcode 3-gram は論文の DG（0.132）が順序を学習していたのに対し、今回の DGAN（0.220）は tcode をシャッフルした基準（0.186）より悪く、順序を学習できていない。実装・前処理の差（後述）が効いている可能性が高い。
4. **どのモデルも日付パターン（DoM）は論文の BF に遠く及ばない。** CTGAN・PAR・DGAN はいずれも DoM が 0.10 前後で、BF の 0.011 と大きな差がある。BF は未実行だが、「汎用の生成モデルは月内の日付パターンを学習しにくい」という論文の主張とは整合する。
5. **ツール側の落とし穴が 3 つあった。** どれも結果を大きく変えるが、エラーにはならない。
   - SDV の CTGAN は既定（`log_frequency=True`）のままだと、生成時のカテゴリ分布が一様分布側に平らになる（Tcode JSD 0.000 → 0.130）
   - pandas 3 の datetime（マイクロ秒単位）を SDV にそのまま渡すと、生成日付が 1970 年付近に化ける
   - gretel 版 DGAN に取引間隔をそのまま渡すと、全取引が同じ日になる系列ばかりを生成した

## 追試の対象

Nickerson et al., *Banksformer: A Deep Generative Model for Synthetic Transaction Sequences*, ECML PKDD 2022 の
Table 2（Czech データ）。論文は Banksformer（BF）を DoppelGANger（DG）・TimeGAN（TG）と 6 つの指標で比較している。

今回は次の 2 点を確かめた。

1. **評価プロトコルの再現**: 論文の前処理と指標を再実装し、DG 相当のモデルで論文に近い傾向が出るか。
2. **CTGAN の素朴な適用**: 論文にない行独立の CTGAN を同じ指標で測り、行単位の指標と系列・日付の指標がどう分かれるか（issue #1 の問い）。

Banksformer 本体の再学習は行っていない（「残課題」参照）。

## 方法

### データと前処理（論文 2 節に準拠）

- 著者リポジトリの前処理済み CSV（Czech bank, 105.6 万取引, 4,500 口座）
- tcode = type × operation × k_symbol（16 種類。論文と一致）
- 口座ごとに日付順に並べ、80 件ずつに分割し、20 件未満の系列を除外 → 14,354 系列
- 口座単位で半分に分割: A（学習用, 7,259 系列）と B（比較用, 7,095 系列）

### 指標

| 列 | 定義 | 出典 |
|---|---|---|
| Amt | 取引金額の Wasserstein-1 距離 | 論文 Table 2 |
| CF | 月次キャッシュフロー（系列×月ごとの入金−出金の合計）の Wasserstein-1 距離 | 論文 Table 2 |
| Tcode | tcode 分布の JSD | 論文 Table 2 |
| DoM | 月内日（1〜31）の分布の JSD | 論文 Table 2 |
| Tcode3G | 系列内 tcode 3-gram の分布の JSD | 論文 Table 2 |
| TcodeDoM | (tcode, 月内日) 同時分布の JSD | 論文 Table 2 |
| TD | 系列内の取引間隔（日）の Wasserstein-1 距離 | 著者コードで集計されているが Table 2 には未掲載 |
| TxPerMonth | 系列×月ごとの取引件数の Wasserstein-1 距離 | 本追試で追加 |

JSD は著者コードに合わせて自然対数（最大値 ln 2 ≈ 0.693）。生成データは学習データ A と比較する（論文も学習データと比較している）。

指標の目安として、実データ B を使った基準を 3 つ併記する。

- **Real-B**: そのまま。同じ分布から独立に取った実データ同士の値
- **tcode シャッフル**: B の tcode だけを全行でランダムに入れ替えたもの。周辺分布は保ち、順序と金額・日付との対応を壊す
- **日付シャッフル**: B の日付だけを全行でランダムに入れ替えたもの。系列の時間構造を壊す（行独立な生成の理想形に近い）

### 比較した手法

| 手法 | 実装 | 学習設定 | 論文との関係 |
|---|---|---|---|
| dgan | gretel-synthetics 0.22.2 の DoppelGANger（PyTorch） | 400 エポック。属性: 年齢・系列開始日、特徴量: tcode・log 金額・log(1+取引間隔) | 論文 DG の再実装版 |
| ctgan | SDV 1.38.5 / ctgan 0.12.1 の `CTGANSynthesizer`、`log_frequency=False` | 50 エポック。1 行 = 1 取引（日付・tcode・金額・年齢）。生成行を 80 件ずつ束ねて系列とみなす | 論文になし。issue #1 の問い |
| ctgan-logfreq | 同上、SDV 既定の `log_frequency=True` | 同上 | 既定設定のまま使った場合の参考 |
| par | SDV の `PARSynthesizer` | 50 エポック。系列キー・日付順・年齢をコンテキスト | 論文になし。SDV の系列手法 |

いずれも生成数は論文と同じ 5,000 系列、乱数シード 0。CPU のみ（12 コア）。所要時間は DGAN 5 分、CTGAN 12〜24 分、PAR 63 分（CTGAN の一方は PAR と並行実行）。

### 論文との差分

| 項目 | 論文 | 本追試 | 影響 |
|---|---|---|---|
| DG の実装 | 元の TensorFlow 実装、可変長系列 | gretel-synthetics の PyTorch 実装、長さ 80 の系列のみで学習・生成 | 系列長の分布は再現対象外 |
| DG の時刻表現 | 開始日＋取引間隔 | 同じ。ただし取引間隔は log1p で圧縮（付録 A） | 生の取引間隔だと崩壊した |
| 生成値の範囲 | 記載なし | DGAN は学習データの範囲にクリップ（SDV 系は既定で同様） | 外れ値の影響を抑える |
| 比較対象の実データ | 学習に使った全データ | 学習用の半分（A） | 系列数が約半分 |
| 乱数シード | 記載なし | 1 シードのみ | ばらつきは未評価 |
| BF・TG | 実行 | 実行せず | BF・TG の行は論文値を転記 |

### 読み取り

**CTGAN は「日付シャッフル」とほぼ同じ振る舞いをする。** TD（18.3 vs 21.4）、TxPerMonth（3.4 vs 3.7）、CF（2,172 vs 2,328）、Tcode3G（0.192 vs 0.169〜0.186）のどれも、実データの日付や tcode を行間で入れ替えた基準と同程度になった。CTGAN が生成した 80 件の「系列」は平均 1,861 日（約 5 年）に散らばっていて、実データの 1 系列（平均 379 日）とは時間の密度がまったく違う。それでも Table 2 の 6 指標では、CTGAN は BF に近い値を出す。

**系列モデルは時間間隔を学習するが、順序・日付パターンは今回の設定では学習できていない。** PAR と DGAN は TD を 2.4〜2.5 まで下げ（CTGAN の約 1/7）、PAR は月あたり件数もよく合っている（0.36）。一方 Tcode3G は 0.22 と tcode シャッフルの基準（0.186）より悪く、取引コードの並び順は再現できていない。DoM と TcodeDoM も CTGAN と同程度で、月末の利息計上のような日付と取引種別の結びつきは学習されていない。

**論文 DG との比較。** DoM（0.107 vs 0.090）と CF の大きさ（4.0 万 vs 5.8 万）は論文の DG と同じ水準で、「DG は日付パターンを学習しにくく、キャッシュフローが大きく外れる」という論文の観察は再現した。一方で次の 2 点は論文の DG と違う。

- Tcode3G: 論文の DG（0.132）はシャッフル基準より良く、順序をある程度学習していた。今回の DGAN（0.220）は学習できていない
- TcodeDoM: 今回の DGAN（0.282）は論文の DG（0.660）よりかなり良い。論文の値は tcode シャッフル基準（0.211）よりも悪く、生成された日付の分布自体が大きく崩れていた可能性がある

固定長への制限、取引間隔の log 変換、PyTorch 実装への置き換えのどれが効いたのかは切り分けていない。

なお、今回の DGAN は系列の開始日（属性）が崩壊していた。生成された 5,000 系列の開始日はすべて 1998 年 5 月以降で、取引日は実データの期間（1993〜1998 年）を越えて 2002 年まで伸びている。月内日や取引間隔の指標には直接効かないが、年・季節に関わる分析には使えない。

**CF は時間構造の指標として解釈しにくい。** 日付シャッフルの CF（2,328）は論文の BF（2,738）より小さい。また、tcode シャッフルの CF（10,817）は日付シャッフルより大きく、CF はむしろ入出金の符号（tcode）と金額の対応に敏感な指標である。CF の小ささを「時系列パターンを捉えた証拠」とする論文 6.1 節の読み方には注意が要る。

## 結論

- 論文の評価プロトコルは再実装できた。DG 相当のモデルで、日付パターン（DoM）とキャッシュフロー（CF）の弱さは論文と同じ傾向が出た。ただし 3-gram と (Tcode, DoM) は論文値と一致しなかった。
- issue #1 の問い（CTGAN を素で適用すると何が壊れるか）への実データでの答え: 行単位・同時分布の指標はほぼ保たれる一方、取引間隔と取引密度が実データの日付をランダムに入れ替えた場合と同じ程度に壊れる。この壊れ方は論文 Table 2 の指標では見えず、TD・TxPerMonth のような時間構造の指標を直接入れないと検出できない。
- 汎用の系列モデル（PAR, DGAN）は時間間隔を改善するが、取引コードの順序と月内の日付パターンは、今回の学習量では BF の水準に届かない。

## 残課題

- Banksformer 本体の再学習。著者コードは TensorFlow 2 のノートブックで、LICENSE がない。リポジトリに取り込まず、別環境で実行する方法を検討する
- 複数シードでのばらつき評価
- DGAN の論文との差（3-gram, TcodeDoM）の切り分け: 可変長系列、取引間隔の表現、エポック数
- ctgan の `sample_original_condvec` が log 頻度を使う挙動の上流への報告（docstring と実装の不一致）

## 付録 A: DGAN の設定による違い

同じ 400 エポック・2,000 系列生成で、取引間隔の渡し方とスケーリングだけを変えた結果（クリップなし）。

| 設定 | 生成された取引間隔の平均（日） | Amt | CF | Tcode3G | TD |
|---|--:|--:|--:|--:|--:|
| 既定・取引間隔そのまま | 0.01 | 3,001 | 224,590 | 0.181 | 5.28 |
| 既定・log1p(取引間隔) | 7.64 | 51,143 | 167,198 | 0.222 | 2.45 |
| example scaling なし・そのまま | 13.82 | 56,871 | 151,250 | 0.431 | 9.94 |
| example scaling なし・log1p | 3.46 | 3,387 | 18,342 | 0.465 | 2.15 |

実データの取引間隔の平均は 5.3 日。既定設定のままだと取引間隔が 0 に潰れ、全取引が同じ日に置かれた。本編では「既定・log1p」を採用し、金額の外れ値は学習データの範囲へのクリップで抑えた。設定次第で指標が 1 桁変わるので、論文の DG の値との比較は幅を持って読む必要がある。

## 再現手順

```bash
uv sync
uv run transyn prepare
uv run transyn fit dgan --epochs 400
uv run transyn fit ctgan --epochs 50
uv run transyn fit ctgan-logfreq --epochs 50
uv run transyn fit par --epochs 50
uv run transyn evaluate
```
