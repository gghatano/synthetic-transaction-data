# DGANと論文DGの差の切り分け

issue #5の成果物。#2の追試（[replication-banksformer.md](replication-banksformer.md)）では、gretel版DGANは論文のDGと
DoM・CFの傾向は一致したが、Tcode 3-gramと (Tcode, DoM) が一致せず、系列開始日（属性）も1998年5月以降に崩壊していた。
設定を1つずつ変えて、どこに原因があるかを調べた。

## 要点

1. **gretel版DGANはシード間のばらつきが大きく、論文のDGとの差を設定の違いに帰着できない。** 同じ設定でもシードによって金額の平均が実データの0.3〜6.6倍、取引間隔のW1距離が2.4〜24.0と大きく変わる。論文値との差よりシード間の差のほうが大きい指標が多い。
2. **どの設定でもTcode 3-gramは論文のDG（0.132）に届かなかった。** 最良はシード1の0.209で、tcodeをシャッフルした基準（0.186）より悪い。取引コードの順序は学習できていない。
3. **取引間隔は「0に潰れる」崩壊が起きやすい。** 取引間隔をlog変換しない場合と、開始日を属性から外した場合の2つで、生成された取引間隔がすべて0になった（TDが実データの平均取引間隔5.28と一致し、月あたり件数は74.5）。
4. **DoMが良く見える崩壊がある。** 開始日を実データから抽出した設定はDoM 0.021と論文のBF並みに見えるが、全取引が実データの開始日と同じ日に置かれた結果で、日付パターンを学習したわけではない。DoMだけを見ると誤判定する。
5. **エポック数を増やしても改善しない。** 1000エポックでは3-gramが0.462に悪化し、開始日の崩壊も残った。

## 方法

基準は #2のDGAN（gretel-synthetics 0.22.2、400エポック、取引間隔はlog1p、開始日は属性として生成、sample_len 10）。
ここから1点ずつ変えた設定を、シード0で学習・生成した（5,000系列）。基準の設定のみシード0〜2の3回（#4）。

| 名前 | 変更点 |
|---|---|
| dgan | 基準 |
| dgan-rawtd | 取引間隔をlog変換せずに渡す |
| dgan-empstart | 開始日を属性から外し、生成後に学習データの系列開始日から復元抽出する（論文のBF・TGと同じ扱い） |
| dgan-sl5 | sample_lenを10 → 5（1回のRNNステップで生成する取引数を減らす） |
| dgan-e1000 | エポック数を400 → 1000 |

実行手順は次のとおり。

```bash
uv run transyn fit dgan-empstart --epochs 400
uv run transyn fit dgan-sl5 --epochs 400
uv run transyn fit dgan-rawtd --epochs 400
uv run transyn fit dgan --epochs 1000 --tag=-e1000
uv run transyn evaluate
```

### 読み取り

- シード間のばらつき: 基準設定の3シードで、Amtは5,058〜33,457、CFは6,883〜94,795、TDは2.43〜23.99と1桁の幅がある。シード2は取引間隔が長すぎる側に崩れ（TD 24.0）、シード0は開始日が1998年に偏った。論文DGとの差（Amt 1,939、CF 57,800）はこの幅に収まっている指標もあり、差の原因を特定の設定に帰着できない。
- 取引間隔の崩壊: dgan-rawtdとdgan-empstartはどちらもTD = 5.28（実データの平均取引間隔と同じ値）、TxPerMonth = 74.5で、80件すべてが同じ日に置かれている。log変換は #2で入れた対策で、外すと崩壊が再発した。開始日を属性から外すとlog変換していても崩壊したので、属性の有無が学習の安定性に影響している。
- 見かけのDoM改善: dgan-empstartのDoM 0.021は、全取引が実データの開始日に置かれたことによるもので、TD・TxPerMonthを見れば崩壊が分かる。#2で述べたとおり、単一の指標で時間構造を判定するのは危険。
- sample_len: 5にするとTDとTxPerMonthは最良になったが、3-gramは0.269に悪化し、開始日の崩壊は残った。
- エポック数: 1000エポックでは3-gram（0.462）・TcodeDoM（0.345）ともに悪化した。学習を長くしても順序の学習には効かない。

## 結論

- gretel版DGANでは、論文のDGの3-gram（0.132）は今回試したどの設定・シードでも再現できなかった。
- 差の主因は特定の設定ではなく、gretel版DGANの学習の不安定さ（シード・設定によって取引間隔・開始日・金額が別々に崩壊する）にあると考える。論文の元実装（TensorFlow版、可変長系列）との差は切り分けていない。
- 実務的には、DGANの結果は複数シード・複数の時間構造指標で確認しないと、崩壊を見逃す。

## 残課題

- 更新回数が少なかった可能性: gretel版DGANのバッチサイズを1,000（系列数が少なければ系列数）にしていたため、学習用の5,573系列では1エポックあたり6回、400エポックで2,400回しか更新していない。ICUバイタルの検証（#15）では、バッチを64に下げて更新回数を増やすと自己相関の再現が大きく改善した。ここでの結論（論文DGの3-gramに届かない、崩壊が起きやすい）は、この設定での結果として読む必要がある

- 論文の元実装（TensorFlow版DoppelGANger）での再実行。#6でBanksformer用に用意したTensorFlow環境を流用できる可能性がある
