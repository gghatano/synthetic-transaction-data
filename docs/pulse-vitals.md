# 生理エンジンPulseで作ったICUバイタルの評価

issue #21の成果物。[シミュレーションの調査](survey-simulation.md)（#18）で挙げた生理エンジンPulse（Kitware、Pulse 4.4）で仮想患者のバイタルを作り、[ICUバイタルの検証](icu-vitals-verification.md)（#15）と同じ指標で評価した。学習型の生成モデルとは違い、Pulseは個人の記録を学習しない。患者の設定（年齢・体格・基準の心拍数と呼吸数・肺炎の有無）だけを学習データの集計値から引き、経過は生理モデルが計算する。

## 要点

1. **Pulseは時間構造で勝り、水準の正確さで劣る。** 揺らぎの足し方を共有したVAR(1)（#15のvar1）と比べた。Pulseは自己相関のずれが小さく（ACF 0.102 対 0.180）、値の分布と滞在ごとの平均のずれは大きかった（Marg 0.354 対 0.215、StayMean 0.341 対 0.202）。自己相関の差は30分・1時間のラグで出ており、ラグ5分ではほぼ同じだった。水準の差はほぼ心拍数から来ていて、Pulseの心拍数の平均は93で、実データの85より高い。
2. **距離に基づくプライバシ指標は、揺らぎの小さい合成データに誤って反応する。** 素のPulseはNearCopy 0.224、DCRRatio 0.658で、学習データをコピーしたように見えた。Pulseは個々の記録を学習していない。この26系列が最近傍としたのは学習データのわずか13滞在で、どれも滞在内の揺らぎが学習データの下位約4%に入る「落ち着いた」滞在だった。揺らぎを足すとNearCopy 0.000、DCRRatio 1.268に戻った。
3. **Pulseの作り方のせいで決まる値は、手法の評価から外す。** 死亡退院はPulseが計算した転帰ではなく、先にくじで決めたラベルなので、TSTR_AUROCとMortalityは他のモデルと比べられない。年齢はPulseの制約で18〜65歳に切り詰めた（実データは18〜90歳）。年齢はMargには入らず、判別スコアと有用性の特徴量に入る。年齢を除くと、揺らぎを足したPulseの判別スコアは0.440から0.362に下がり、VAR(1)は0.380のまま変わらなかった。

## 方法

### 仮想患者の作り方

`external/pulse/run.py`。学習用A（716滞在）から次の集計値を推定し、120人分の設定を引いた。個々の滞在の値はそのまま使っていない。

- 死亡退院の割合と、死亡退院ごとの性別の割合
- 性別×死亡退院ごとの（年齢、身長、体重、入室後1時間の心拍数・呼吸数の平均）の多変量正規分布
- 呼吸器の診断（呼吸不全・肺炎・ARDS）がある割合。死亡退院ごとに求め、その確率で両肺の肺炎（重症度0.05〜0.3）を与えた

Pulseの有効範囲に合わせ、年齢18〜65歳、基準の心拍数50〜110、基準の呼吸数8〜20、BMI 16〜29.9に切り詰めた。Pulse 4.4の敗血症は、設定項目はあるが生理モデルに組み込まれていないため使わなかった。

各患者について5分ごとに144点（12時間）、心拍数・SpO2・呼吸数を出力した。120人のうち4人（15, 36, 37, 91）は初期化に失敗し、評価に使ったのは116人。1人あたり約40〜80分、12並列で全体に約13時間かかった。

### 揺らぎを足した版（pulse-noise）

素のPulseは滞在内の揺らぎが小さい。系列内の標準偏差は、実データAに比べて心拍数で約0.6倍、SpO2で約0.1倍、呼吸数で約0.07倍しかない。そこで、var1と同じ仕組みで作った揺らぎをPulseの出力に足した版も作った（`vitals-pulse-noise`）。揺らぎの仕組みは次のとおり。

- 学習データから、滞在内で標準化した変動の変数間VAR(1)を推定する
- 滞在ごとの標準偏差の分布（logをとった多変量正規分布）を推定する

この版の目的は補正ではなく切り分けにある。var1とpulse-noiseは揺らぎの仕組みが同じで、違いは「揺らぎの下にある滞在ごとの経過」がVAR(1)の定数か、Pulseの計算した推移か、だけになる。そのためPulse固有の寄与は、実データとの差ではなくvar1との差で見る。

### 評価

指標は#15と同じ12個に、年齢を除いた判別スコア（Disc_noAge）を加えた。Pulseは116系列しかないので、実データの基準と各生成モデルからも116系列を非復元で抜き出し、20回の平均をとった（`vitals-evaluate --n 116`）。学習データAと評価用Bは全体を使う。生成モデルはシード0の結果だけを使った。

### Pulse固有の寄与（pulse-noiseとvar1の差）

- 揺らぎの仕組みを共有しているので、Corr（0.046 対 0.049）、PSD（1.406 対 1.276）、StayStd（0.271 対 0.268）はほぼ同じだった。これらの値はPulseではなく、足した揺らぎの性質を表している。素のPulseからの改善（Corr 0.334 → 0.046など）を「Pulseが回復した」と読んではいけない。
- 自己相関はPulseが良い。変数・ラグ別に見ると、ラグ5分のずれはどちらも0.02〜0.05で差がない。ラグ1時間では、心拍数の自己相関が実データ0.356に対しpulse-noise 0.231、var1 0.02で、var1は1時間後にはほぼ相関が残らない。Pulseの計算した30分〜1時間単位のゆっくりした推移が、VAR(1)の短い記憶を補っている。ただし呼吸数はPulseの出力がほぼ一定なので、ラグ1時間の自己相関はpulse-noiseでも0.001で、var1と変わらない。
- 水準はPulseが悪い。心拍数の値の分布のずれ（Marg）はpulse-noise 0.466に対しvar1 0.078、滞在ごとの平均のずれは0.420対0.069だった。素のPulseでも心拍数のMargは0.438で、揺らぎを足す前から出ている。Pulseの心拍数の平均は93で、実データAの85より高い。仮想患者に与えた基準の心拍数は平均87.6で、実データAの入室後1時間の平均（88.0）とほぼ同じだった。ところがPulseの出力は最初の5分で91に上がり、8時間目まではそのまま、最後の4時間で98まで上がった。実データの心拍数は入室後1時間の88から12時間全体の85へと下がっていくので、向きが逆になっている。SpO2はvar1も同程度にずれていて（Marg 0.412 対 0.387）、呼吸数は差が小さい（0.183 対 0.099）。
- 判別スコアは、年齢を含めるとpulse-noise 0.440、var1 0.380。年齢を除くと0.362と0.380になり、年齢の制約がpulse-noiseの判別スコアのうち約0.08を占めていた。年齢を除いた値でpulse-noiseがvar1をわずかに下回るが、Pulseは116系列全体を毎回使うため抜き出しのばらつきがなく、この差（0.018）が意味のある差かは判断できない。「年齢を除けば同程度」と読むのが妥当。素のPulseは年齢を除いても0.496で、揺らぎの小ささだけで見分けられる。

## プライバシ指標の誤反応

素のPulseのNearCopy 0.224は、学習データのコピー（Copy-A）を除けば全行で最も高い。DCRRatio 0.658も、合成系列が評価用Bよりも学習データに近いことを示す値で、文字どおりに読めば記憶による漏洩を疑うことになる。

しかしPulseは個々の記録を学習していない。NearCopyに該当した26系列を調べると、最近傍は学習データの13滞在に集中していた。その13滞在の滞在内の揺らぎ（標準化した値の標準偏差）は中央値0.225で、学習データ全体の中央値0.454の半分ほどしかなく、全体の下位約4%に入る。揺らぎのほぼない系列は、標準化した空間で「落ち着いた実患者」の近くに集まる。そのため、特定の個人を写していなくても最近傍距離が小さくなる。揺らぎを足したpulse-noiseではNearCopy 0.000、DCRRatio 1.268に戻った。最近傍がどの滞在かに依存しないMIA（0.501）は、素のPulseでも反応しなかった。

この罠はPulseに限らない。距離に基づく指標（DCR、NearCopy）は、分散を過小に再現した合成データ、つまりモード崩壊気味の生成モデルや平滑化しすぎたモデルでも同じように反応する。そのような合成データを「プライバシが危ない」と誤って判定しうる。逆に、学習データを写していても揺らぎが大きければ反応しにくい。距離に基づく指標を読むときは、合成データの滞在内の分散が実データと揃っているかを先に確かめ、最近傍が少数の学習記録に集中していないかも見る必要がある。

## 比べられないもの

- **TSTR_AUROCとMortality**: 死亡退院はPulseが計算した転帰ではない。実データの死亡率でくじを引いて先に決め、その値で基準の心拍数・呼吸数と肺炎の有無を条件付けしたラベルである。ラベルとバイタルのつながりは、その条件付けを通じた分しかない。値は参考として下に載せるが、他のモデルとは比べない。Mortality（0.008）も、くじで決めた割合をそのまま反映しているだけで、評価にはならない。

  | | TSTR_AUROC | Mortality |
  |:--|--:|--:|
  | pulse | 0.436 | 0.008 |
  | pulse-noise | 0.513 | 0.008 |

- **年齢**: Margは心拍数・SpO2・呼吸数の3変数だけで計算していて、年齢の切り詰めは効かない。効くのは判別スコアと有用性の特徴量で、判別スコアへの影響はDisc_noAgeで切り分けた。
- **#15の全量評価との比較**: 116系列に揃えたため、実データCの判別スコアは0.053（全量では0.000）、有用性は0.671（全量では0.776）と、基準自体が変わっている。この表の値を#15の表の値と並べてはいけない。

## 制約

- 足した揺らぎの大きさが実データより大きい。滞在内の標準偏差はpulse-noiseで心拍数11.9、SpO2 3.07（実データAは6.9、1.85）で、約1.7倍ある。SpO2は約13%の点が上限の100%に、約1%が下限の51%に切り詰められた。同じ仕組みのvar1も大きめに出る（心拍数8.7、SpO2 2.9）。この結果はvar1とpulse-noiseが同じ仕組みを共有していることを前提にした比較で、実データCとの絶対的な近さは主張しない。揺らぎの大きさを変えるとvar1と#15の結果も作り直す必要があるため、今回は直していない。
- 自己相関でのPulseの優位は、足した揺らぎの大きさに依存する。素のPulseはラグ1時間の自己相関が0.6前後と高すぎる。足す揺らぎが大きいほど、その分だけ自己相関が薄まる。
- Pulseは1シード・116人だけで、シード間のばらつきは測っていない。1人あたり40〜80分かかるため、これ以上は増やしていない。
- 敗血症など、ICUに多い病態の多くはPulse 4.4では与えられない。今回与えた病態は肺炎だけ。

## 再現手順

```bash
# Pulse 4.4 を data/pulse/ にビルドする（C++17 コンパイラ、make、uv が必要）
bash external/pulse/build.sh
# 仮想患者のバイタルを作る（12並列で約13時間）
cd data/pulse/build/install/bin
PYTHONPATH=../python:. ../../../venv/bin/python ../../../../../external/pulse/run.py --n 120 --workers 12
cd -
uv run transyn vitals-pulse-noise                    # → outputs/vitals/gen_pulse-noise_s0.csv.gz
uv run transyn vitals-evaluate --n 116 --draws 20    # → outputs/vitals/results_n116.md
```

#15の生成結果（outputs/vitals/gen_*_s0.csv.gz）も、同じ評価に含まれる。評価は約3分。
