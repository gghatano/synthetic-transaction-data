# 見本用データの忠実度の段階と公開前チェック

GHE issue 9の成果物。見本用の合成データ（学外に「こういうデータを取った」を伝えるもの）は、忠実度を下げてよい代わりに、何を保ち何を保たないかを明示し、公開前に開示リスクを確かめる必要がある。表データ向けの2つの枠組みを、被験者ごとの時系列に当てはめた。

- 英国統計局（ONS）の合成データの6段階（Bates, Špakulová, Dove, Mealor. *ONS methodology working paper series number 16 – Synthetic data pilot*, 2019, https://www.ons.gov.uk/methodology/methodologicalpublications/generalmethodology/onsworkingpaperseries/onsmethodologyworkingpaperseriesnumber16syntheticdatapilot ）。低い順に synthetic structural、synthetic valid、synthetically-augmented plausible、multivariate plausible、multivariate detailed、replica。著者は「synthetic data」という呼び名を最初の2段階に限ることを提案している（一般の人は合成データに開示の問題がないと考えるため）
- Raab, McCall, Cavin. *Four checks for low-fidelity synthetic data*（arXiv:2503.14211, 2025）。低忠実度の合成データの公開前に、表示（実データでないことを明示する）・開示リスク・構造（元データにできるだけ近い構造）・文書化（構造の違いを記録する）の4つを確かめる

## 要点

1. **段階ごとに、狙った性質だけが実データに近づいた。** 値の分布はL1で実データ同士並み（ずれ0.062、実データ同士0.058）、自己相関はL2で0.45から0.18、被験者ごとの平均はL3で0.49から0.26（分位点で切り詰めると0.18）、死亡退院による平均心拍数の差はL4で5.5 bpm（実データ6.2 bpm）になった。それより下の段階では、その性質は保たれない（たとえばL0〜L3では死亡退院による差が−0.1〜1.1 bpm）。
2. **どの段階でも、合成データは実データと見分けられた。** 判別スコアは0.43〜0.50（実データ同士0.00）。見本用データは「本物らしいデータ」ではなく、「保つと明記した性質を持つデータ」として扱うのが妥当。
3. **既定の生成では、実在の被験者の極値がそのまま現れた。** 3変数の最小・最大のうち、その値をとる被験者が10人未満のものが、L1〜L4で平均1〜3個、合成データに現れた。L1は実データの値を引くため、L2〜L4は生成後に学習データの最小・最大で切り詰めるため（公開リポジトリの#15以来の既定）。値を学習データの0.5〜99.5パーセンタイルで切り詰めると0個になり、被験者ごとの平均・ばらつきやスペクトルのずれはかえって小さくなった。
4. **その他の開示リスクの指標は、どの段階でも小さかった。** 1時間（12点）の3変数の値が実データのどこかと完全に一致する合成系列は0件、メンバーシップ推論のAUCは0.48〜0.50。ただし学習データとの近さ（DCRRatio）は段階が上がるほど1に近づき（L0の1.92からL4の1.15）、学習データにごく近い系列がL3・L4で2%出た。
5. **公開前チェックを、表示・開示リスク・構造・文書化の4つの関数とコマンドにした。** `uv run transyn showcase-release --level L3` で、実在しないID（`SYN-L3-00000`）の見本用データ、保つ性質・保たない性質と用途を書いたメタデータ、チェック結果をまとめた説明書きを書き出す。

## 方法

### 段階

| 段階 | 作り方 | 保つもの | ONSの段階との対応 |
|---|---|---|---|
| L0 | 成人の一般的な参考範囲（心拍数50〜120、SpO2 88〜100、呼吸数10〜30、年齢18〜90、死亡退院10%）から一様に引く。実データを使わない | 項目・単位・5分間隔・144点の記録長 | synthetic structural |
| L1 | 変数ごとに、学習データの全時点の値から独立に復元抽出。年齢・死亡退院も独立 | ＋変数ごとの値の分布 | synthetically-augmented plausible |
| L2 | 滞在内で標準化した変動に当てたVAR(1)で変動を作り、全員共通の平均・標準偏差に載せる | ＋被験者内の時間構造、変数間の相関 | multivariate plausibleの一部 |
| L3 | 被験者ごとの平均・log標準偏差を多変量正規分布から引き、L2の変動を載せる。年齢・死亡退院とは無関係 | ＋被験者ごとの違い | multivariate plausible |
| L4 | L3を死亡退院の有無ごとに推定し、年齢も含めて引く（#15のVAR(1)と同じ） | ＋年齢・死亡退院との関係 | multivariate detailed |

学習データA（716滞在）から各段階716人分を3シードで作り、学習に使っていない実データCと比べた。L1〜L4は、既定（学習データの最小・最大で切り詰め）と、0.5〜99.5パーセンタイルで切り詰めた版（-clip）の両方を作った。

### 公開前チェック（4つのチェックの時系列向けの具体化）

| チェック | 中身 | 実装 |
|---|---|---|
| 表示 | 実在しないID（`SYN-<段階>-<番号>`）に付け替え、合成である旨・段階・作り方・保つ性質・保たない性質・用途・元データ・作成日をメタデータに書く | `showcase.label` |
| 開示リスク | 1時間（12点）の3変数の値の、実データとの完全一致の件数。その値をとる被験者が10人未満の極値が合成データに現れる数。人数が10人未満の群（死亡退院の有無など）。DCRRatio・メンバーシップ推論のAUC・NearCopy（#15と同じ） | `showcase.disclosure_checks` |
| 構造 | 列（並びは問わない）、系列ごとの時点数と時刻番号、生理的にありうる範囲（#15の範囲）、欠測なし | `showcase.structure_checks` |
| 文書化 | 保つ性質・保たない性質と、チェック結果を説明書きに書く | `showcase-release` の README |

### 見本から読み取れる関係

見本を受け取った人が読み取りうる関係として、死亡退院の有無による平均心拍数の差（HRDiffDied）と、年齢と平均心拍数の相関（AgeHRCorr）を測った。

実行手順は次のとおり。

```bash
uv run transyn vitals-prepare
uv run transyn showcase-evaluate                 # 段階ごとの評価 → outputs/showcase/results.md
uv run transyn showcase-release --level L3       # 見本用データとチェック結果 → outputs/showcase/release_L3/
```

所要時間はどちらも数分。

### 読み取り

- 段階を上げると、その段階で足した性質の指標だけが改善し、他は前の段階のまま。たとえばL1はL0から値の分布だけが改善し、自己相関はL0と同じ0.449のまま。見本用データの仕様書に書く「保つ性質」と、実際の指標が対応している。
- 有用性（死亡退院の予測）は段階と単調に対応しない。L1（0.629）がL4（0.599）より高いのは、L1の死亡退院のラベルが値と無関係にもかかわらず、評価用Bの実データでの予測が偶然の範囲（標準誤差約0.05）でぶれたためと考えられる。見本用データの品質を有用性で測るのは向かない。
- 極値の再現は、L1では実データの値をそのまま引くことから、L2〜L4では学習データの最小・最大での切り詰めから起きた。後者は生成モデルの外れ値を抑えるための処理で、#15以来の既定だった。分位点で切り詰めると、VAR(1)が裾で作る極端な被験者の平均・ばらつきが抑えられ、被験者ごとの平均のずれ（0.255 → 0.176）やスペクトルのずれ（1.466 → 0.980）がかえって小さくなった。
- 学習データとの近さはL3で大きく変わる（DCRRatio 1.71 → 1.18）。被験者ごとの平均・ばらつきを学習データの分布から引くと、合成した被験者が実在の被験者の近くに来やすくなる。メンバーシップ推論のAUCは変わらないので、特定の人が見分けられるほどではない。
- L4の見本では死亡退院による心拍数の差（5.5 bpm）が読み取れる。しかし、それを見本上で検定すると偽陽性が増える（GHE issue 1、[synthetic-inference.md](synthetic-inference.md)）。関係を保つ段階ほど、「分析には使わない」という表示が重要になる。

## 見本用データへの示唆

- 「こういうデータを取った」を伝える目的なら、L2（時間変化の様子まで）かL3（被験者ごとの違いまで）で足りる。属性や条件との関係を見せるL4は、研究結果の先出しになりうるうえ、受け取った側が分析に使う誘因が大きい。
- 生成後の値は、学習データの最小・最大ではなく、分位点（例: 0.5〜99.5%）で切り詰める。実在の被験者の極値を出さずに済み、忠実度も下がらない。
- 公開前には、4つのチェックを毎回行う。特に、少人数の群（10人未満）で条件を分けて生成しないこと（GHE issue 3、[small-n-generators.md](small-n-generators.md)）。
- ONSの提案に従えば、L0〜L1は「合成データ」、L2以上は「合成で増強したデータ」と呼び分け、後者は開示リスクの評価を前提にする。

## 制約

- 段階はバイタル3変数・12時間の系列で作った。イベント系列（EHR）や取引のような不規則な間隔の系列では、段階の切り方が変わる
- 開示リスクの評価は、距離・完全一致・極値に基づく。属性推論（一部の属性から残りを推測する攻撃）は試していない
- 極値の判定は「その値をとる被験者が10人未満」とし、公開の生理的な範囲の端と同じ値（切り詰めで誰にでも出る値）は除いた（GHE issue 14で定義を直し、表の値を更新した。直す前はL1〜L4で2.3・1.0・4.0・3.7個）。しきい値は仮の値
- 学習データ716人から作った。研究室規模（数十人）の学習では、L3・L4の推定がぶれる（GHE issue 3）
